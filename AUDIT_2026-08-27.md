## 1. Executive Summary (Резюме проекта)

**MeDev (DevProfile)** — это data-first SaaS-платформа для IT-специалистов, автоматизирующая сбор данных об опыте разработчика из GitHub, генерацию ATS-совместимых резюме с помощью LLM (Groq API) и трекинг откликов на вакансии через интерактивный Kanban ATS.

### Ключевые метрики на 27.08.2026:
- **Бэкенд:** Spring Boot 3.3.0, Java 17, PostgreSQL 17 (pgvector), Redis (Valkey 8.1.4), Flyway (24 миграции).
- **Фронтенд:** React 19, Vite, TypeScript, Tailwind CSS v4, Zustand, Feature-Sliced Design (FSD).
- **Покрытие тестами:** 
  - **Бэкенд:** 253/253 автоматизированных тестов (100% Green — `@WebMvcTest`, `@SpringBootTest`, Service Unit Tests).
  - **Фронтенд:** 37/37 тестов (100% Green — Vitest + React Testing Library).
  - **Предупреждения сборки / Линтер:** 0 ошибок, 0 ворнингов.
- **Инфраструктура:** 
  - Backend API: Render Web Service (`https://medev-backend.onrender.com/api`).
  - Frontend SPA: Vercel (`https://me-dev-two.vercel.app`) + GitHub Pages (`https://mrsgemaseny.github.io/MeDev/`).
  - База данных: Render PostgreSQL 17 + Flyway V24.
  - Кэш: Render Redis + In-Memory Caffeine (L1).

## 3. Детальный аудит модулей системы

### 3.1. Модуль аутентификации и безопасности (`auth`, `security`)
- **Статус:** [PASSED] Высокая надежность.
- **Реализация:** Stateless JWT. Refresh-токены хранятся в Redis с TTL 30 дней.
- **Защита от коротких ключей:** В `JwtService` внедрен `@PostConstruct` валидатор секрета (длина строго $\ge 32$ байт / 256 бит).
- **IDOR & RLS:** Доступ к ресурсам жестко валидируется через `SecurityUtils.getCurrentUserId()`. Доступ к чужим профилям, откликам и резюме на уровне сервисного слоя невозможен.
- **Криптография:** Все чувствительные токены и токены интеграций шифруются в базе через `AES-256-GCM` (`EncryptedStringConverter`).

### 3.2. Модуль профиля и синхронизации с GitHub (`profile`, `github`)
- **Статус:** [PASSED] Высокая надежность.
- **Реализация:** Загрузка репозиториев, определение языков программирования, сбор коммитов и генерация матрицы навыков.
- **Защита от Race Conditions:** Все мутирующие операции используют пессимистическую блокировку (`getProfileEntityForUpdate(userId)` / `PESSIMISTIC_WRITE`).
- **Снимки GitHub:** Внедрена таблица `github_snapshots` (миграция V20) для фиксации состояния репозиториев без повторных тяжелых запросов к GitHub API.

### 3.3. Модуль публичного портфолио и двухуровневого кэширования (`portfolio`)
- **Статус:** [PASSED] Оптимизировано под высокие нагрузки.
- **Реализация:** Публичный эндпоинт `/api/v1/portfolio/:username` защищен двухуровневой системой кэширования:
  - **L1 In-Memory Caffeine:** Отдача профиля за микросекунды без сетевых задержек.
  - **Инвалидация кэша:** Реализован `PublicProfileCacheEvictListener` с привязкой к `TransactionSynchronizationManager.afterCommit()`, что исключает race condition при обновлении профиля.
  - **Rate Limiter:** 60 запросов/минуту на публичные эндпоинты через `PublicRateLimiter`.

### 3.4. Модуль ИИ и генерации резюме (`ai`, `resume`)
- **Статус:** [PASSED] Стабильно.
- **Реализация:** Проксирование запросов к Groq LLM API (`openai/gpt-oss-20b`), генерация текста через Server-Sent Events (SSE).
- **PDF Engine:** Сборка PDF через Thymeleaf + Flying Saucer + PDFBox. Поддержка кириллических шрифтов (Roboto) локально (без внешних `@import`).
- **Защита ресурсов:** Лимит токенов (4096), автоматическая санитизация JSON/Markdown и закрытие потоков ввода-вывода (try-with-resources).
- **PRO-Gate:** Проверка платной подписки (`assertPro`) на тяжелых ИИ-функциях и премиум-шаблонах резюме.

### 3.5. Модуль трекинга вакансий (`tracker`)
- **Статус:** [PASSED] Полная интеграция.
- **Реализация:** Интерактивный Kanban ATS со стадиями откликов (APPLIED, INTERVIEW, OFFER, REJECTED).
- **Связь с профилем:** Привязка откликов к конкретным резюме и сохранение истории взаимодействий.

### 3.6. Модуль биллинга и платежей (`billing`)
- **Статус:** [PASSED] Готов к коммерциализации.
- **Реализация:** Поддержка Stripe Webhooks и локального эквайринга Kaspi Pay.
- **Идемпотентность:** Обработка вебхуков защищена через Redis-блокировки по `orderId` / `eventId`.

### 3.7. Модуль аудита и администрирования (`audit`, `admin`)
- **Статус:** [PASSED] Соответствие Enterprise-стандартам.
- **Реализация:** `AuditService` логирует события аутентификации, изменения тарифов, админские действия и IP-адреса в таблицу `audit_logs` (миграция V19).

## 4. Нагрузочное тестирование и стресс-анализ (Chaos Engineering)

25 августа 2026 г. было проведено боевое нагрузочное тестирование боевого сервера Render Free (0.1 CPU, 512MB RAM):

| Тест | Параметры нагрузки | Результат | Поведение системы |
|---|---|---|---|
| **Spike Test v1** | 100 RPS (40 сек, 1600 VU) | 418 × `200 OK`, 231 × `500`, 1375 timeouts | Исчерпание пула соединений HikariCP при тяжелых JOIN. Сервер не упал по памяти. |
| **Spike Test v2 (Cache)** | 100 RPS (40 сек, 1600 VU) | 506 × `200 OK`, 0 × `503`, 1358 timeouts | Кэширование дашборда сняло нагрузку с базы. |
| **Tsunami Test** | 500 RPS (45 сек, 10 500 VU) | 188 × `200 OK`, **6 901 × `429 Too Many Requests`**, 8 456 timeouts | **Сервер выжил (Graceful Degradation).** Bucket4j Rate Limiter отбил 7000 запросов без обращения к БД, предотвратив OOM-crash. |

### Выводы по надежности:
1. **JVM Stability:** Архитектура выдерживает спайки в тысячи пользователей без падения процесса (нет `OutOfMemoryError`).
2. **Graceful Degradation:** Защитные барьеры (Bucket4j + In-Memory Caffeine + Hikari Timeout 10s) переводят пиковую перегрузку в безопасные ответы `429` / `504` вместо краша контейнера.

## 5. Фронтенд-архитектура и UI/UX (FSD Review)

### Структура слоев (Feature-Sliced Design):
- `app/` — Провайдеры, роутер, инициализация темы и глобальных стилей.
- `pages/` — Страницы (Dashboard, Profile, Resume, Tracker, Landing, Billing, Admin).
- `widgets/` — Композитные блоки (Navbar, Sidebar, Landing Widgets: Hero, Features, Pricing, Header, Footer).
- `features/` — Бизнес-фичи (Profile editing, AI chat widget, Resume generator, GitHub sync).
- `entities/` — Бизнес-сущности и стейт-менеджмент (User store via Zustand, Profile models).
- `shared/` — Переиспользуемые UI-компоненты, API-клиенты, утилиты, хуки, темы.

### Дизайн-система:
- **Стиль:** Строгий GitHub Dark Mode (`#0d1117` фон, `#161b22` карточки, `#30363d` границы, `#238636` акцент).
- **Чистота:** Полное отсутствие ресурсоемкого Glassmorphism, теней и несемантических цветов.
- **Адаптивность:** Полная поддержка мобильных экранов (375px+).

## 6. Технический долг и точки роста (Gap Analysis)

| Область | Описание проблемы | Критичность | Рекомендуемое решение |
|---|---|---|---|
| **PDF Generation** | Синхронная генерация PDF в потоке запроса. При 3+ одновременных запросах нагружает слабый CPU. | **[WARNING]** | Внедрить `ThreadPoolTaskExecutor(core=1, max=2)` и асинхронный паттерн `202 Accepted` со скачиванием по ссылке. |
| **RAG Vector Search** | `VectorizationService` генерирует эмбеддинги в `pgvector` (V18), но `vectorStore.similaritySearch()` еще не подключен к UI. | **[INFO]** | Подключить семантическое сопоставление резюме с текстом вакансии в модуле `tracker`. |
| **Мониторинг** | Отсутствует сбор логов ошибок на проде в реальном времени. | **[WARNING]** | Подключить Sentry на фронтенде и бэкенде; настроить Prometheus/Grafana метрики. |
| **Кастомный домен** | Работа на субдоменах `onrender.com` и `vercel.app`. | **[INFO]** | Привязать production-домен (например, `medev.dev` / `medev.kz`) с Cloudflare CDN. |
| **Бэкапы БД** | Автоматические бэкапы зависят от настроек Render. | **[WARNING]** | Настроить cron-дампы PostgreSQL в S3/Cloud Storage. |
