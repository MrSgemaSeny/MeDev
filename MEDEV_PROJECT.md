## 1. Суть проекта

MeDev — это data-first платформа для разработчиков.

**Главная идея:** один раз собери всё о себе → используй везде.

Сегодня разработчик тратит часы на то чтобы:
- написать резюме в Word/Canva/каком-то генераторе
- поддерживать портфолио на отдельном сайте
- обновлять GitHub README вручную
- переписывать одно и то же в каждом новом месте

MeDev решает это через единый профиль. Подключил GitHub, загрузил старое резюме — платформа
собрала всё в один структурированный профиль. Дальше из него генерируется всё остальное.

---

## 2. Три продукта внутри одного

### 2.1 Публичная страница-портфолио
```
app.com/username
```
Красивая публичная страница разработчика. Можно отправить HR вместо резюме.
Подтягивает данные из единого профиля — стек, проекты, активность, языки.

### 2.2 Генератор резюме по шаблонам
Выбираешь шаблон → данные уже заполнены из профиля → экспортируешь PDF.
Не нужно ничего вводить заново. Белый A4, но красивый. Несколько визуальных тем.

### 2.3 Конструктор резюме по секциям
Drag-and-drop редактор. Сам решаешь какие секции включить, в каком порядке,
что показывать а что скрыть. UX — главный приоритет этого модуля.

## 3. Как работает профиль (data-first)

```
Источники данных:
┌─────────────────┐   ┌──────────────────┐   ┌────────────────┐
│  GitHub API     │   │  Загрузка резюме │   │  Ручной ввод   │
│  - репо         │   │  PDF → парсинг   │   │  (опционально) │
│  - стек         │   │  → данные        │   │                │
│  - активность   │   └──────────────────┘   └────────────────┘
│  - контрибьюшны │
└─────────────────┘
          │                    │                      │
          └────────────────────┴──────────────────────┘
                               ↓
                    Временное хранилище (Redis)
                    Пользователь редактирует, дополняет
                               ↓
                      Единый профиль (PostgreSQL)
                    ┌──────────────────────────────┐
                    │  personal_info               │
                    │  experience[]                │
                    │  education[]                 │
                    │  skills[]                    │
                    │  languages[]  ← важно        │
                    │  projects[]   ← из GitHub    │
                    │  achievements[]              │
                    │  social_links{}              │
                    └──────────────────────────────┘
                               ↓
          ┌────────────────────┼────────────────────┐
          ↓                    ↓                    ↓
   Портфолио страница   Генератор резюме    Конструктор
   app.com/username     (шаблоны → PDF)    (drag&drop)
```

## 4. Секции профиля

Каждая секция независима — можно показывать/скрывать в резюме:

- **Личная информация** — имя, фото, контакты, локация, сайт
- **О себе** — краткое описание (как в резюме)
- **Опыт работы** — компания, роль, период, описание, стек
- **Образование** — университет, специальность, период
- **Навыки / Стек** — языки, фреймворки, инструменты (из GitHub + ручной)
- **Проекты** — выбранные репо с описанием, стеком, ссылками
- **Языки** — казахский, русский, английский + уровень (A1-C2 / native)
- **Достижения** — сертификаты, награды, публикации
- **Социальные ссылки** — GitHub, Telegram, LinkedIn (опц.), личный сайт

## 5. Монетизация

- 1 шаблон

## 6. Целевая аудитория

**Основная:** разработчики любого уровня (junior → senior)
- Студенты которые ищут первую работу
- Джуны которые хотят нормально представить себя
- Мидлы/сеньоры которым лень тратить время на резюме

**Старт:** СНГ рынок (Казахстан, Россия, Украина, Беларусь)
**Рост:** глобально — мультиязычность интерфейса и резюме с первого дня

**Будущие сегменты (не в MVP):**
- Дизайнеры (Behance интеграция)
- Продакты
- Фрилансеры

## 7. Конкуренты и отличие

| Продукт | Проблема |
|---------|---------|
| Стандартные генераторы резюме | Перегружены или пусты, кривые редакторы |
| Canva резюме | Красиво но нет GitHub интеграции, не для разработчиков |
| read.cv / polywork | Не работают, мертвые продукты |
| LinkedIn | Перегружен, специфическая аудитория, не про резюме |
| Ручной HTML/Canva | Красиво но требует дизайн навыков и времени |

**Главное отличие MeDev:**
1. Data-first — вводишь один раз, используешь везде
2. GitHub парсинг — стек и проекты подтягиваются автоматически
3. UX редактора — drag-and-drop, легко добавить/удалить/переставить
4. Для разработчиков — не универсальный инструмент, а заточен под dev-аудиторию

## 8. Стек

| Слой | Технология | Почему |
|------|-----------|--------|
| Backend | Java 17 + Spring Boot 3 | Знакомый стек, production-ready |
| БД | PostgreSQL + Flyway | Надёжно, миграции |
| Кэш | Redis | Временное хранение профиля до сохранения |
| Auth | JWT + Spring Security | Stateless, знакомо |
| GitHub интеграция | GitHub REST API v3 | OAuth + парсинг репо/статистики |
| PDF парсинг | Apache PDFBox / Tika | Извлечение текста из загруженного резюме |
| PDF генерация | iText / Flying Saucer | Генерация красивого PDF из HTML шаблона |
| Frontend | React 19 + TypeScript + Vite | Знакомый стек |
| Drag-and-drop | dnd-kit | Лучшая библиотека для React, гибкая |
| Стилизация | Tailwind v4 | Быстро, знакомо |
| State | React Query + Zustand | Query для сервера, Zustand для редактора |
| Деплой backend | Fly.io | Уже знакомо по ZhanFinance |
| Деплой frontend | Vercel / GitHub Pages | Быстро, бесплатно |
| Платежи | Stripe (глобал) + Kaspi (СНГ) | Два рынка — две системы |

## 11. Ключевые технические решения

### GitHub парсинг
```
GitHub OAuth → access_token → GitHub API:
GET /user                    → имя, фото, bio, локация
GET /user/repos              → список репо
GET /repos/{owner}/{repo}/languages → стеки по репо
GET /users/{username}/events → активность (для графика)
```
Пользователь выбирает какие репо показывать в профиле.

### PDF парсинг (загрузка чужого резюме)
```
Пользователь загружает PDF →
Apache Tika извлекает текст →
Structured parsing → заполняет поля профиля →
Пользователь проверяет и корректирует →
Сохраняем в БД
```
Не 100% точность — пользователь всегда может поправить.

### PDF генерация (экспорт резюме)
```
Профиль + выбранный шаблон →
HTML шаблон (Thymeleaf / Freemarker) →
Flying Saucer → PDF
```
Шаблоны — это HTML/CSS файлы. Легко добавлять новые.

### Drag-and-drop редактор (dnd-kit)
```typescript
// Секции резюме — массив с порядком
const sections = ['experience', 'education', 'skills', 'languages', 'projects']

// DndContext оборачивает весь редактор
// SortableContext — список секций
// useSortable — каждая секция
// onDragEnd → обновляем порядок в Zustand → сохраняем в БД
```

## 12. UX принципы (самое важное)

1. **Ноль friction при онбординге** — подключил GitHub, уже есть профиль
2. **Каждое действие в 1 клик** — добавить секцию, удалить, переставить
3. **Preview в реальном времени** — меняешь данные, резюме обновляется рядом
4. **Ничего не теряется** — скрыть секцию ≠ удалить, данные сохраняются
5. **Мобильный просмотр** — публичная страница адаптивная (редактор — десктоп)

## 14. Риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| PDF парсинг даёт мусор | Высокая | Пользователь всегда редактирует вручную |
| GitHub API rate limit | Средняя | Кэш в Redis, токен пользователя |
| Drag-and-drop сложнее чем кажется | Высокая | dnd-kit зрелая библиотека, MVP без лишних эффектов |
| Stripe недоступен в КЗ | Низкая | Kaspi как основной для СНГ, Stripe через VPN |
| PDF генерация сложные шаблоны | Средняя | Начать с простых A4 шаблонов, усложнять постепенно |
